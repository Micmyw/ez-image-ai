EzPic submits image changes as generation jobs. The client sends a stable product key; Provider
routing, model identifiers, credentials, and cost details remain on the server.

Availability, aspect ratios, and input limits come from the server, so the interface does not promise
a product or setting that the service has disabled. Each product has its own valid setting matrix;
the interface does not combine a quality or resolution from one product with another. One confirmed
edit produces one image. Output format and background controls, where a product supports them, do
not change the EzPic Credit charge and do not create additional SKU combinations.

## Job status

After submission, the result panel reports the current stage and progress. A job can finish
successfully, fail, or be canceled only when the server reports that cancellation is allowed.

## Results

A successful image edit provides a before-and-after comparison. Download requests use an
owner-scoped, short-lived access URL rather than exposing storage credentials or a permanent public
object URL. The **Edit again** action can carry the result into a new editing job while preserving the
eligible parent relationship.
