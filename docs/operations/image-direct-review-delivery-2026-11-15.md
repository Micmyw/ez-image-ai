# 模型完成后的连续审核与展示

状态：2026-11-15 本地实现并验证，尚未提交、推送或部署。没有调用生产生图模型，也没有以本地用例耗时推算线上提速。

## 正常链路

`media-poll-generation` 鉴权读取并确认模型完成后，在同一次请求中登记私有输出，复用已经打开的原图流准备 SeeAPI 审核图片，并执行审核。无需先退出当前 Workflow 步骤、交接给存储执行器，再创建一个审核执行阶段。

收到有效通过结论后，提交审核证据与 `READY`。注册用户的授权读取、游客结果快照均可在此时返回图片；输出归档、结算和相关事件收尾不是展示前置条件。

| 原测量阶段                       | 本次处理                                                                                 |
| -------------------------------- | ---------------------------------------------------------------------------------------- |
| 输出登记、启动审核               | 在确认模型完成的请求内连续执行，移除跨执行器交接；私有资产、来源与恢复意图仍须原子登记。 |
| 领取任务、读取原图、准备审核图片 | 复用本次已检查的原图流，避免重新打开源地址；完整哈希、格式校验和审核图片准备仍保留。     |
| 保存处理中状态、等待再次查询     | 短审核在同一个验证租约内查询已绑定任务；无需每轮写入 PENDING、退出、重新领取。           |
| 收到通过结论、提交可展示状态     | 移出输出对账与结算准备；最小审核证据、READY 与后续事件仍原子提交。                       |

“跳过四段”指移除其中的额外交接和展示前置工作，不能省略真实图片校验和审核结论的可靠提交。R2 原先已独立，本次也没有重新增加 R2 展示门槛。

## 边界和恢复

- 沿用 `MEDIA_PROVIDER_ORIGINAL_DELIVERY_ENABLED=true`，需要已有 Workflow 身份。适用于单张 Kie URL 图片：PNG/JPEG/WebP 保持已知大小且不超过 20,000,000 字节的入口；GPT Image 2.6 的 SVG/GIF 扩展到相同并行链路，已知大小不超过现有 25 MiB 图片上限。
- 游客仅在 Cloudflare Images 处理环境走直接路径；仍审核和交付相同的确定性水印版本，不增加游客 SVG/GIF 权限。多输出、未知大小和其他不适用结果保留现有路径。
- SeeAPI 返回处理中时，本次租约内的短查询默认间隔为 1 秒，最多 15 次，并受 15 秒墙钟窗口约束。遵守响应的 `Retry-After`；官方文档规定新任务的 HTTP 202 响应初次等待 2 秒，即使该响应缺失头字段也按 2 秒处理。后续 GET 没有更长提示时才按 1 秒查询。只增加查询频率，不增加推理提交次数；仍不能宣称浏览器在 SeeAPI 实际完成的瞬间出现图片。
- 靠近审核截止时间、租约到期或短查询窗口结束时停止短等待；长审核转回原有 5 秒持久查询恢复，并保留供应商要求的更长等待时间。429 等错误立即退出短查询，走原有故障退避。所有查询仍检查当前租约与 Workflow 所有权，绝不重新提交已经受理的审核任务。
- 拒绝、服务故障、身份不符和未知结果保持原有拦截/恢复规则。只有明确的无存储写入预检退出可以回到原处理路径；未知错误不会触发另一路付费提交。
- READY 后，原先登记的 finalization/review 意图由同一个 Workflow 的明确事件列表继续消费，保留租约、回执和幂等性，不把正常完成遗留给全局扫描。
- 没有修改视频或模板审核，没有新增数据库迁移或环境变量；上线仍需部署实际执行这些处理函数的 Jobs/Workflows 产物。
