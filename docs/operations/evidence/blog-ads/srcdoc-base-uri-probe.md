# Local canary probe: iframe fallback base URL

This security follow-up used only a harmless local host URL whose query was `canary=SYNTHETIC_AD_BASE_URI_CANARY_20261011`. It loaded no vendor script, payload, creative, or production page and performed no ad click. Source files and `.source` were not changed. The full result, copied parent CSP, frame values, violations, and fixture strings are in `srcdoc-base-uri-probe.json`.

The child frames always had `sandbox="allow-scripts"` and `referrerpolicy="no-referrer"`. Each used a fresh independent Chromium context. The child script only set `window.canaryProbeRan=true`; browser inspection read the DOM values. In `<base>` cases, the browser then removed that element inside the child to demonstrate fallback behavior.

| Case                                                                   | Child result                                                                                                                                               | Implication                                                                |
| ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| `srcdoc`, no parent CSP                                                | `document.baseURI` is the full parent URL with canary; `document.URL` and location are `about:srcdoc`; referrer is empty                                   | Opaque origin and no-referrer do not isolate the fallback base URL         |
| `srcdoc`, copied original parent CSP                                   | Same canary exposure                                                                                                                                       | The original policy does not remove the inherited fallback                 |
| `srcdoc` with vendor-host `<base>`, original CSP                       | `base-uri 'self'` rejects that base; fallback still exposes canary                                                                                         | The vendor-host base cannot be used under the original policy              |
| `srcdoc` with own-origin root `<base>`, original CSP                   | Initially the base URI is the public root; removing the base restores the full canary URL                                                                  | A removable base tag is not a security boundary against child script       |
| `srcdoc` with child meta CSP allowing vendor base, original parent CSP | Parent `base-uri 'self'` still rejects vendor base                                                                                                         | Child meta CSP cannot relax the inherited parent policy                    |
| `srcdoc` with child meta `base-uri 'none'`, no parent CSP              | Fallback still exposes canary                                                                                                                              | Restricting base tags does not sanitize the inherited fallback             |
| `data:text/html,...`, no parent CSP                                    | Base URI, document URL and location are the static data URL; referrer is empty; canary absent; harmless child marker runs                                  | Static data transport does not inherit the embedding query as its fallback |
| `data:text/html,...`, copied original parent CSP                       | Console reports `frame-src https://challenges.cloudflare.com` violation; frame becomes `chrome-error://chromewebdata/`; harmless child marker does not run | Original CSP blocks the entire data document                               |

The copied parent policy retained the original `base-uri 'self'`, `script-src`, and `frame-src` directives. Other copied directives match the production template without optional storage-origin additions; those additions do not affect these base/frame checks. Every resulting context had no cookies. Attempting to read parent location from a loaded opaque child remained denied, which did not prevent the separate base-URI disclosure.

A loaded `data:` child can still see the parent's public origin through `location.ancestorOrigins`. The probe recorded only `http://127.0.0.1:64459`, without the parent path or canary query. Data transport therefore protects the embedding URL's path/query fallback in this probe; it does not hide the existence of the hosting origin.

The HTML standard defines an iframe `srcdoc` document's fallback base using its embedding document, and [MDN's iframe documentation](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe#srcdoc) explicitly describes this relative-URL behavior. [MDN's base-uri documentation](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/base-uri) describes the directive as restricting `<base>` URLs. The canary results distinguish that restriction from the independently inherited fallback.

The prepared implementation now uses static `data:text/html,...` content with no host URL or user data interpolated into it, preserving the original CSP and disabled advertising switch. It remains intentionally blocked by the current `frame-src`; this probe supports the transport's confidentiality property and does not authorize any policy change or certify supplier compatibility. A removable `<base>` in `srcdoc` is insufficient.
