# Video pricing availability and unrelated releases

Price approval expiry no longer stops valid new ordinary-video, Hotel Lobby, Raindance or Rumpelstiltskin orders. This removes the expiry mechanism; no new deadline, price, credit amount or credential is supplied. The legacy `VIDEO_PRICE_VALID_UNTIL` and `HOTEL_LOBBY_DUO_PRICE_VALID_UNTIL` fields remain readable in older private bundles but are inert, cannot create flat/packed conflicts, and are omitted from newly packed runtime policy. The old build-only expiry override is also ignored. Version, complete-cost, revenue, provider/model, safety, funding and authorization checks remain mandatory.

Hotel Lobby and Raindance options are assessed independently for each 5- and 10-second selection. Known missing/unconfirmed/invalid optional policy returns `available: false` with a fixed source reason and does not block unrelated fixes. The capability endpoint returns public `TEMPLATE_UNAVAILABLE`; upload, quotation and first job creation still refuse that invalid option. The existing approved retail totals are shared with new-order admission: standard/annual prices stay 69/69 and 116/101 with the same markups. Drift is unavailable both at build assessment and runtime admission. Rumpelstiltskin and legacy non-retail prices are outside that fixed retail tuple.

Malformed private JSON, non-retired flat/packed conflicts, invalid explicit policy override transport, ordinary-video readiness and other pricing failures, required global authentication/database/storage settings and unknown exceptions still stop preparation. Unknown resolver errors use a fixed fatal diagnostic without exposing arbitrary text. New packing filters only retired fields; it does not alter feature flags or the remaining opaque policy.

New pricing snapshots use `priceApprovalExpiryMode: none` and `validUntil: null`. Existing snapshots and ledger entries are not rewritten. Accepted confirmation replay still checks the persisted admission before any current new-order price guard. Its owner-scoped history, signed playback/download, safety and emergency recovery checks remain. A historical price-approval deadline no longer aborts an otherwise valid accepted order before a provider call.

Release the jobs consumer first and drain executors still using the retired price-deadline checks before releasing the website producer. Older scene consumers require a finite future `validUntil` and cannot safely receive the new `none/null` snapshots. New consumers accept both historical and new snapshots. Independent automatic website/jobs builds do not establish this release order; the release operator must enforce it. No synthetic future deadline is supplied for compatibility.

Quote TTL remains finite. Asset/session expiry, reviewed-content evidence, Rumpelstiltskin motion reference review and rights, subscriptions, annual-price eligibility and explicit internal funding authorization deadlines remain enforced by their separate checks. Rumpelstiltskin pricing records `referenceValidUntil` as diagnostic metadata; the actual reference gates remain authoritative and are not converted to price gates. Future-dated approval evidence still fails its original not-yet-effective check.

Verification uses synthetic policies, local PostgreSQL-only contracts where available, and mocked external boundaries. It does not certify current production policy or live provider/payment requests. No schema migration, stored snapshot rewrite, policy renewal or production configuration change is included.
