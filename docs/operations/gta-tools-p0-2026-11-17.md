# GTA image tools P0

The local implementation adds `/gta-6-wallpaper` and `/gta-loading-screen-generator` to the existing SaaS application. Both pages have their own English metadata, self-canonical, server-rendered content, scene illustrations, instructions and FAQs. Their entries are maintained in the existing navigation, public routing matcher and sitemap editorial dates.

## Product behavior

| Task        | Initial draft                                 | Input                                           | Local result tools                                                                 |

| Wallpaper   | Beach Sunset, Phone, 9:16                     | One portrait or an environment without a person | Screen preview, standard/tall phone and desktop crops, source-pixel PNG export     |
| Loading art | Neon Boulevard, Desktop, 16:9, portrait right | One portrait                                    | Left/right generation composition, clean image or editable name, static PNG export |

Both tasks share Beach Sunset, Neon Boulevard, Sports Car, Rooftop Skyline, Marina Blue Hour and Palm Road. Settings compile an explicit versioned prompt. The complete prompt, effective reference, product, SKU and ratio enter the existing quote and submission fingerprint. The accepted prompt carries a fixed public header that identifies the theme, task, scene, input mode, format, position and prompt version.

Settings update the draft. GTA requires a paid subscription, spendable purchased credits, or a qualifying Image Pass. Guest/free allowance cannot fund new GTA tasks. The existing Generate action submits the task. Quote preparation retains its existing credit-free, job-free behavior. Account credit funding, subscriptions, Image Pass, guest eligibility, moderation, reservations, settlement and recovery remain owned by the existing generation procedures. The change adds no concurrency or daily admission limit.

GTA defaults to GPT Image 2.6 Sunburst. Customers may change models and tiers; paid access is independent of that choice. The shared catalog supplies model selection, quality, size, supported static formats and pricing. The current MiniMax H3 contract includes both 9:16 and 16:9 at its 1K, 2K and 4K cells. A model's loaded SKU controls supported layouts, and a mismatched layout blocks quotation/submission. During catalog loading the GTA controls can still prepare the requested draft. The browser and server retain the existing complete admission checks.

Scene mode suspends the reference in the request while retaining the selected photograph for a switch back. It also omits temporary reference credentials and the edit parent. Photo mode requires a usable reference and retains the existing permission, expiry and review feedback.

## Drafts, access and export

The workbench restores public preset choices before mounting the private editor. Signed-in drafts and upgrade recovery use owner-scoped, route-specific storage slots. Signing out clears the current owner's added slots and matching return pointer. Returning from login or payment restores the draft and current pricing. Submission remains an explicit user action.

Shared links contain the canonical path and a bounded fragment made from scene, format, portrait position and input mode. The clipboard fallback displays that same safe link in a read-only field. Private job/return query parameters stay out of the shared link. Existing private query states keep their noindex policy.

Result tools use the accepted task's composition. The next draft cannot move an existing result's name area. Names are plain text, limited to 24 grapheme clusters where supported, with automatic fitting, wrapping and font fallback. Name contents stay in browser component state and are masked from session replay.

Export refreshes the existing private access URL, loads a bounded decodable Blob and draws from its object URL. The crop uses source pixels and performs no enlargement. Device frames, clocks and icons are separate preview layers. Guest exports redraw the existing guest watermark geometry after cropping or name composition. An export failure retains the image and local settings for retry.

The owner explicitly selected the built-in image-generation tool for these examples. Six phone environment wallpapers, two desktop wallpapers, two portrait wallpaper studies and three loading-art studies are shipped, together with three synthetic reference portraits. There were sixteen built-in generation/edit calls.

Public assets live in `apps/saas/public/images/gta/`. WebP previews and downloadable JPEGs retain their measured dimensions. One vertical loading study was cropped in source pixels to 892 × 1586, with its exact crop recorded. The source portraits depict fictional adults.

`docs/operations/evidence/gta-artwork-2026-11-17.json` records each artifact's original identity, complete generation prompt, source relationship, dimensions, hashes, public display/download permission and visual review. Its `productPipelineRun` is false and its model ID is null because the built-in tool exposed no model identifier. The public examples are labeled Style preview or Original AI artwork.

These assets establish the commissioned visual direction. Real-provider likeness, latency and billing behavior for these new prompts require separate product-pipeline receipts. The local verification uses the repository's controlled boundaries for those services. Live checkout and production deployment are outside the evidence obtained in this implementation.

## UI and behavior review follow-up — 2026-11-17

The review fixes keep uploads, pricing, authorization and submission in the existing signed-in and guest forms. A presentation-only `ToolComposerProvider` places the GTA scene and composition controls inside those forms, before model selection and submission. It hides the raw preset and generic prompt suggestions. Optional additional instructions retain the complete preset, survive scene/side changes and stay out of shared URLs. Legacy manually edited prompts remain preserved until the user confirms replacement.

The editor now has a full-width upload area, a compact six-scene grid, collapsible additional instructions and scoped teal/coral styling. The phone and desktop controls appear before submission on mobile. The loading-art summary identifies a static image with PNG name export; instructional copy follows the trial or credit option actually shown by the shared form.

Preview selection requires an exact task, scene, photo/scene mode, format and portrait-side match. A missing illustration displays a labeled composition guide at the selected ratio instead of falling back to unrelated or incorrectly shaped artwork. Guides are not downloadable result images. Switching between a guide and a generated wallpaper preserves its applied crop, and generic tool results do not receive Christmas labels.

The local name state survives scene, format, sample/result and output-asset changes, including anonymous-session bootstrap. A different registered owner starts with empty name state. Accepted output composition remains frozen while editing the next draft. Preset changes synchronize the current URL fragment and optional public session preference, so refresh no longer restores an obsolete shared preset.
