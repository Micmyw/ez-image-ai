# 已审核模型原图交付与独立归档

日期：2026-11-14。实现仅在本地；没有提交、推送、部署或启用生产开关。

## 用户确认的行为

已通过输出审核的完整模型图片可以展示、下载、继续编辑并按现有资金合同结算。R2 是独立归档副本，其成功不再是这些操作的前置条件。小审核图仅用于 SeeAPI 检测，用户收到的是完整尺寸图片；游客仍收到带水印的完整尺寸结果。

## 实际执行顺序

1. 现有模型回调唤醒经过认证的供应商结果查询。保存任务绑定、原图来源及两个 Outbox 意图；保留现有输入和资金事务协议。
2. 审核流程直接读取供应商原图，核对完整长度和 SHA-256，并制备现有 1568px 审核 JPEG，随后调用 SeeAPI。这里没有 R2 HEAD/GET/PUT 前置依赖。
3. 独立 `MEDIA_OUTPUT_ARCHIVE` / `media-archive-output` 流程同时开始归档。Workers 用请求级 transfer 服务，转换或恢复使用既有 heavy 路径。归档唤醒登记到请求的 `waitUntil` 生命周期；无托管生命周期时同步等入队响应。持久 Outbox 始终保留。
4. SeeAPI 审核通过后，资产变为 `READY`，前端立即提供查看、下载和继续编辑。`FINALIZING` 父任务可用的查询和事务准入均已放开；真实审核、所有权和信用额度条件保持。
5. R2 完成只更新 `MediaOutputOrigin` 的归档回执，不改变审核证据和结果状态。结算仍通过原有不可变、幂等账本；不会因归档失败重发生成请求。

供应商并没有自动替网站调用 SeeAPI。是网站收到并确认生成结果后立即启动独立审核，不等待 R2 存储。

## 私有访问及身份

新图片使用 `provider-original-v1/users/<owner>/assets/<asset>/original.<ext>` 的私有资产标识。`/api/media/original` 使用最多 300 秒的签名访问凭证；浏览器不会收到供应商临时地址。普通访问仍要求当前完整审核证据有效，管理后台独立签署 `admin` scope，并保留原有管理员授权及查看审计。

未归档时，访问网关从供应商读取完整图片并核对审核时冻结的 SHA-256/长度，符合后才输出。归档回执匹配时读取 R2；R2 不可用时可回退同一摘要的供应商原图。删除、过期和撤回审核在返回前重查。未审核、拒绝、哈希变更的图片不能通过普通链接访问；签名 scope 不可由客户提升。

服务器的签名读取、HEAD、范围读取、图片检查及复制也支持原图标识，避免继续编辑等消费者又落回“必须先有 R2 对象”。后续重新审核可从匹配的已归档副本制备，不依赖已经失效的供应商 URL。

## 恢复和删除

归档有独立租约、容量预留和有限重试。归档故障只记录归档错误，不把已成功结果改为失败。定时恢复包括过期归档租约、领取归档前丢失的 Outbox 执行响应，以及扫描器入队成功后 Workflow 未领取归档的情况；恢复不受图像任务是否已成功限制。

归档与审核先后顺序都核对身份；归档摘要不同会标记 `ORIGINAL_ARCHIVE_IDENTITY_CHANGED`，不能替换已审核原图。删除之后才完成的写入，即使旧租约已失效，仍计入容量并产生准确对象的清理意图。已有所有者/管理员删除授权和图片自动删除暂停规则继续执行。

## 支持范围

- 新鲜远程 URL、JPEG/PNG/WebP、响应长度明确且在 20,000,000 字节以内，走新的并行路径。
- Workers 游客输出使用同一个 Cloudflare Images 实现制备、审核、下载及归档水印图；不写干净的中间原图，因此不伪造 `cleanStagingDeletedAt`。已有游客审核和过期条件保留。
- 混合 Node/Workers 部署下的新游客输出继续旧链路，避免 Sharp 与 Images 产生不同字节；启用后已有未归档游客原图必须继续使用相同 Images 实现，直到完成归档。
- GIF 全帧审核、SVG 专用处理、inline 图片、未知长度、较大图片及既有旧协议恢复任务继续原链路。此轮没有宣称这些路径也绕过归档。

供应商 URL 的保留期限未获新的服务保证。如果 R2 持续失败直至原地址失效，后续读取可能暂时不可用；新协议不会据此重发付费生成或改写已完成账本。此风险独立于用户已收到的成功结果，保留在归档诊断中。

## 发布与回滚顺序

1. 先应用 `20261114141753_provider_original_delivery` 和 `20261114141800_provider_original_private`，包含 RLS、浏览器角色撤权和应用角色权限。
2. 在生产者保持关闭时部署所有消费者：网站访问/复用、审核、结算、归档、Outbox/Workflow、定时恢复和管理员查看。混合配置需要兼容 Node 接收端。
3. 排空不认识 `MEDIA_OUTPUT_ARCHIVE` 的旧接收端后，再把服务器变量 `MEDIA_PROVIDER_ORIGINAL_DELIVERY_ENABLED` 设为严格的 `true`。示例配置默认为 `false`；不是浏览器变量。
   原生 Git 构建使用专用 `MEDIA_PROVIDER_ORIGINAL_DELIVERY_BUILD_ENABLED=true` 覆盖同一运行时变量；两个构建目标保持一致，避免下一次发布恢复旧配置。该构建变量不进入浏览器或构建子进程环境。
4. 回滚先关闭新生产者，保留新消费者和表，直到所有原图资产及待归档任务完成。不能直接回到仅理解 R2 资产的旧版本。

## 验证范围

隔离 PostgreSQL 回归覆盖审核不依赖 R2、慢写期间成功结算、真实 SeeAPI 适配器的模拟 POST/GET、同任务查询不重复提交、游客水印状态、两种完成顺序、归档失败独立重试、失去执行响应恢复、晚写与删除，以及归档未完成时继续编辑的真实事务。

存储测试使用真实图片处理和模拟 HTTP/S3 边界，验证原图摘要、截断/错内容拒绝、水印一致性、重新审核及原图复用。API/UI/Workflow 回归覆盖私有访问、管理员 scope、防撤回、按钮和传输路由。浏览器组件基准、workerd 请求生命周期和类型检查的最终运行结果由本轮交付说明记录。

这些证据不等于线上 R2、Cloudflare Images、SeeAPI 或付费模型联调，也没有测得线上提速秒数；Sharp 的水印一致性测试不能替代真实 Images 联调。
