## 修复与边界

| 范围                | 当前行为与证据                                                                                                                                                                                |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| PayPal / Waffo 退款 | 订阅及积分包的成功退款会回收对应积分。支持累计部分退款、全额退款，以及 PayPal sale/capture reversal。重复事件不会重复回收；部分退款后再发生全额撤款，累计回收以原付款为上限。                 |
| 已用及预占积分      | 已消耗的退款积分形成债务；占用中的退款积分不因任务释放而重新可用，结算成功则形成相应债务。新增回归覆盖两个渠道的并发退款与释放/结算两种结果。                                                 |
| 年付、取消续费      | 年付仍按月发放；取消自动续费后保留已付期限内权益及后续月度积分。全额退款撤销该付款覆盖的未来发放；付款重放不能恢复已退款额度。                                                                |
| 部分退款权益        | 按比例回收积分，年付从较早的积分周期开始分配回收。只要该付款未全额退回，原已付期限内的模型权益仍有效，避免只退一部分钱却暂时降为 Free。                                                       |
| 付款人变更          | 绑定本人 Checkout 后允许更换 PayPal 付款人。历史 Purchase 保持原付款人，旧订阅回调不能覆盖新付款人映射。                                                                                      |
| 到期与二次订阅      | ACTIVE 必须有实际付款且在已付期限内才能获得权限和积分包加赠。仅本地到期不能证明渠道停止续费，因此继续保留取消入口并阻止第二笔自动续费。                                                       |
| 漏回调              | 从两个渠道的认证通知历史补拉原始事件，经原有 PaymentEvent / Outbox 处理。固定窗口、分页游标、租约和重叠窗口保证失败时不跳过页面。每个渠道独立分页续跑，一个渠道失败仍执行其他渠道及本地维护。 |
| 旧退款失败队列      | 只对旧版“退款未支持”错误且现已能验证格式的事件，带审计地重新入队。其他无效身份、金额和关联错误不被批量放行。                                                                                  |
| 未完成 Checkout     | 定价页提供已有付款链接及状态检查。确认从未付款且已关闭后才能解除防重；已付后取消、但付款回调尚未到达的订单会等待履约，避免丢失已付权益。                                                      |
| 收款开关            | `BILLING_ENABLED=false` 服务端阻止新订阅和新积分包，隐藏可选支付渠道；已有付款捕获、回调、退款、取消和维护继续工作。                                                                          |
| 生产环境隔离        | 真实环境的新购要求显式标记环境的 BillingPlan；混合 live/test 或数据库保留未隔离的测试付款事实时拒绝新购。原始事件记录其验签环境，不把历史未知事件自动标为真实付款。                           |
| 价格与返回页        | 订阅计价版本与图片计价版本分离。图片调价不再使未变化的套餐失效。返回页必须有付款及有效期限证据，不能仅凭 ACTIVE 显示成功。                                                                    |

下述历史验证之后，已继续补齐全额退款自动取消续费与确认后立即重订，见
[退款终止修复记录](2026-09-15-refund-subscription-termination.md)。普通取消和部分退款规则不变。

PayPal 的取消 API 不支持 `APPROVAL_PENDING`。已有未批准链接可恢复，但在它仍可被批准时，
不能安全地开放另一个套餐/渠道。此处保留防重复收款限制，不声称已支持即时跨套餐切换。

同日补查了“PayPal 退款后改用 Waffo”和反向流程：新增 6 个检查，覆盖同套餐月付/年付
并发开单，以及两个方向的退款、取消、到期重订和新旧事件重放。该文件 22 项与账户级
订阅防重文件 17 项合计 39 项通过。到期后新订阅只发放一次当期积分，旧退款积分不恢复。

前轮“全额退款并取消后仍需等原到期日”的限制已由本日后续修复替代：最新付款全额退款
会撤销权益并排队关闭续费；仅在渠道确认关闭后允许立即重订。该规则按账户/组织统一执行，
适用于月付、年付套餐；一次性积分包仍可重复购买并保留单笔订单幂等。
渠道仍在取消中的等待不等于已经确认关闭，例如 Waffo `canceling` 仍需后续确认。

本次根据退款后重订讨论补查，确认并修复了一个额外的付费权限缺陷：有多期付款时，
最新一期全额退款后进入 `PAST_DUE`，旧查询仍会借更早的未退款付款维持宽限期权限。
独立 PostgreSQL 回归在修复前返回付费订阅，修复后返回空。宽限期现依据已经开始的
最新已付款周期及其金额退款情况判断；未付的续费周期不覆盖上一笔有效付款，未来周期
不能提前授予权限。部分年付退款中某月积分已回收、但整笔付款尚未全退时仍保留权益。
付款返回页同步修正，避免显示与真实权限不一致的生效结果。

PayPal、Waffo 两期付款 → 最新付款全额退款 → 逾期通知 → 新旧付款/退款重放的处理链路
也已通过：用户保持 Free，最新积分维持已退款状态，原发放账本没有重复。后续退款终止
修复持久化旧权益终止及续费关闭证据，迟到的真实新扣款保留为显式金融复核事件。

通知补拉不是完整交易总账重建。超过 30 天的历史缺口会明确失败；渠道未生成通知的交易仍需
人工核对。此类情况不能靠本地自动扩大发放或忽略错误处理。
