# 全额退款后的订阅终止与重订

基线：`6e0978679cc43518949bc1e591bf6dabbfc9ea58`。
范围：PayPal / Waffo 月付和年付，积分包仍可重复购买。
本次替代“退款不自动取消续费、取消后仍等原到期日”的旧产品限制。

## 最终规则

- 最新付款累计全额退款或全额撤款：积分回收、债务记账和终止请求在同一事务落库。
  年付当前及未发放月份一起处理，付费权限立即停止。
- 通过原始订阅、结账意图、所有者、套餐和已验证支付环境定位原渠道合同。
  取消前后都查询渠道状态。请求成功或超时本身均不能证明续费已关闭。
- 续费关闭确认之前，所有渠道的月付/年付新购继续被账户级锁拦住；确认后立刻允许重订，
  支持换渠道、同套餐和月年互换，历史周期日期保留。
- `refundTerminationRequestedAt` 是永久权益隔离标记；`refundTerminatedAt` 是关闭确认。
  迟到的激活、逾期、取消和原付款重放不能恢复旧权益，也不能影响新订阅。
- 旧订阅出现未知的新付款 ID 时，保留原始已验签 PaymentEvent、死信原因和审计记录，
  使用 `PAYMENT_PROVIDER_TERMINATED_SUBSCRIPTION_PAYMENT_REVIEW_REQUIRED` 进入金融复核。
  不自动发积分，也不将实际收到的钱静默丢弃。
- 部分退款和旧付款退款不取消新的已付款周期。普通取消保留已付期限和原重订日期。
  新订阅积分先偿还旧退款债务，未完成生成任务的退款积分保留原有消费/释放记账规则。

## 取消与恢复

`SUBSCRIPTION_REFUND_TERMINATION` 由原 Outbox 投递至
`media-terminate-refunded-subscription`，确认关闭并落库后才 ACK。
失败保留安全错误码并按 Outbox 退避重试；每小时订阅维护重新排队已耗尽或错误确认的
待终止任务，不覆盖仍有效的投递租约。维护也会识别升级前已经完成的当前全额退款，
用原调整记录和事件环境补齐终止请求，不重复修改账本。
已验签的渠道关闭回调会唤醒待重试的取消检查；回调本身不提前放开重订。

PayPal `CANCELLED` / `EXPIRED`、Waffo `canceled` / `closed` 才确认关闭。
Waffo SDK 0.19.1 的 `docs/api-reference.md` 将 `canceling` 定义为已向 PSP 发起取消，
且仍可由客户撤回，因此保持等待，直到查询确认终止。如果渠道仅在周期结束时完成关闭，
仍受这一渠道行为限制；应用不额外等待旧的本地到期日。

未知环境、错误合同、接口不可用、取消处理中均不会伪装成取消成功。账单页显示等待或
重试，不再显示退款后仍享有套餐；等待期间每 15 秒刷新。生产预检新增未确认终止计数。
套餐选择采用刷新后的购买状态，防止已打开的账单页在取消完成后仍因旧服务端套餐值锁住。

## 发布边界

新增迁移：`20260915075642_subscription_refund_termination`，仅增加 5 个可空字段，
不改余额、不删除历史、不重写支付环境。它必须先于读取新字段的站点和任务代码部署。
前轮尚待生产应用的 4 个迁移仍需一并处理；生产迁移状态检查继续保留。

Git 合并/推送、远程 CI、生产部署、商户真实收款是不同结果。本次发布代码不自动应用
生产迁移、不更换商户 Live/Prod 配置，也不发起真实扣款或退款。真实商户确认、取消时延
和完整付款/退款证据仍按[生产切换手册](../operations/payment-production-cutover.md)验证，
生产真实支付认证保持 `NOT_COMPLETED`，直到相关外部证据齐备。
