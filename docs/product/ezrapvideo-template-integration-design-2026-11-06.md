# ezrapvideo 视频模板融入 EzPic：产品与体验设计

日期：2026-11-06（Asia/Shanghai）

状态：用户已授权实施；本地代码与回归验证完成，未提交、推送、部署或运行付费生成。实施证据见 [实施计划](../superpowers/plans/2026-11-06-ezrapvideo-template-integration.md)，启用条件见 [接入说明](../operations/ezrapvideo-template-integration.md)。

## 1. 已确认方向与设计决策

用户确认：**视频模板与图片工具并列，增加统一视频模板入口，保留首页图片定位。**

用户补充：**可以直接使用 ezrapvideo 的示例提示词和代码。** 因此采用“原提示词/模板逻辑优先复用，适配 EzPic 边界”的方案；不重新编写一套近似模板。用户随后要求“开始实现”，已完成本地实施。

用户进一步明确的硬约束：**不要重复造轮子；提示词、内置场景图与生成方式不能猜测或重新生成。**

样片展示修正：核对 Airap 的 R2、D1 与静态目录后，复用 Flying Car 原始封面/视频；目录展示 9 个真实样片卡片。尚无对应公开样片的 EzPic Hotel Lobby、Raindance、Rumpelstiltskin 保留为 3 个紧凑工具入口，继续支持搜索和分类，不渲染大面积空白预览。样片存在不代表生成已开放。

- 模板原文、源项目已经实现的动态拼装/分镜、人物引用次序、原始场景图/姿态图/动作/音频引用、provider/模型/模式/参数与生成阶段作为保真基线。
- 复用源项目的真实执行方式，不自行选择“看起来等效”的模型，不用生成新场景图替代现有内置图，不把直接引用流程改成“先生成场景再生成视频”。
- 原始生成引用按字节/hash 核对，存储迁移只改变受控地址与授权方式；展示封面/低清预览可从现有公开样片派生，但不能回流替换原始生成参考。
- 缺少实际配置或素材时记录缺项，继续其他模板的独立工作；不按名称、示例画面或文案反推 prompt，不制造占位配置冒充可用模板。
- 优先复用两站现有组件和纯逻辑，新增代码限定为必要适配与缺少的目录；不先建设新的模板 DSL、万能工作流引擎或独立计费系统。

推荐形成三个互通入口：公开模板目录 → 模板创作页；现有视频生成器 → 选择模板；图片结果 → 使用这张图片制作视频。复用 EzPic 的账户、有效积分、私有素材、任务和设计语言。

比较过三种产品路径：

| 路径                                     | 收益                                   | 代价                                   | 决策           |
| ---------------------------------------- | -------------------------------------- | -------------------------------------- | -------------- |
| 视频模板与图片工具并列，首页继续聚焦图片 | 有清楚的发现入口，也能承接独立视频需求 | 需要模板目录与统一创作壳               | 用户选择       |
| 仅从图片结果进入模板                     | 首页改动少，图片到视频路径短           | 视频用户难以发现；无法独立承接模板搜索 | 保留为辅助入口 |
| 重做为图片/视频共同主导的首页            | 更全面地表达多媒体能力                 | 改变现有定位，首页更重，改造范围扩大   | 本次不采用     |

以下为设计建议，不等于用户已经批准具体 URL、定价、模型替换或上线计划。默认原 ezrapvideo 继续运行；本次“使用全部模板”指模板能力纳入目标清单，不包含账户、订单、余额和历史任务搬迁，也不关闭原站。

## 3. 信息架构：统一发现，逐个模板有自己的地址

推荐保持现有顶层分组，在 AI Video 内改成：

```text
AI Image     AI Video ▾     Image Tools     Models     Resources     Pricing
             ├─ 视频生成器
             ├─ 视频模板              /video-templates
             ├─ 原创说唱              /video-templates/original-rap
             └─ 视频指南
```

不把每一个模板塞进全站导航。登录工作区提供同一个“视频模板”入口；无需新增第三套账号侧栏。现有 Rumpelstiltskin 入口保持其账户边界，再逐步收敛到目录中的有权限入口。

**首页**：H1 和图片生成器保持原任务；生成器之后安排一排最多 4 张编辑推荐模板，位于图片核心价值内容之后。标题“让你的照片动起来”，链接“查看全部视频模板”。桌面使用静态封面，手机最多先展示 2 张；不用首屏视频背景，不把模板网格插入图片表单内部。

**模板目录 `/video-templates`**：可匿名浏览；注册后生成。目录只装载公开投影，不读取每张卡的账户状态。首次 SSR 输出卡片和可点击链接。

- 一级内容分类：全部、说唱、舞蹈、宠物动作；“精选”是编辑排序，而非宣称真实热度。
- “单人/双人/三人/人宠”是人物组合筛选；“横屏/竖屏”“有声/无声”是输出属性。
- “生日/节日/对战”等用途仅在真实预设和样片完成后出现；歌词工具不混入视频模板数量。
- 原创说唱的 4 个风格在其页面内选择，可作为带 preset 的目录入口，但不重复统计为独立产品。
- 首版模板较少，优先明确分类和完整列表；超过约 20 项或搜索行为证明有需求时再加搜索。不能以模板目录建设为由制造几十个空分类页。
- 每卡只显示：封面、名称、一句结果说明、输入数量、时长/比例、声音状态、可信的公开起价（有则显示）、“使用模板”。价格不可靠时用“进入后查看报价”，禁止占位 0 credits。

**地址策略**：新目录和新模板使用 `/video-templates` 命名空间，避开旧图片 `/effects` 的 Blog 重定向规则，也避开受保护的 `/video` 布局。

- 现有 Hotel Lobby 继续 `/video-effects/hotel-lobby-ai`。
- Raindance 继续以 `/blog/raindance-ai-trend` 为公开内容身份。
- Rumpelstiltskin 继续 `/video/effects/rumpelstiltskin` 的认证边界。
- 目录卡可以直接指向这些原有页面，统一 UI 不要求先改所有 URL。
- 新页面如 `/video-templates/bulin-47`、`/video-templates/58th-floor`、`/video-templates/spin-me-round`。
- 源站 Hotel Lobby 如保留不同效果，使用明确的新身份和工作名“Hotel Lobby Rap”；正式命名以实际输出核验为准，绝不覆盖原 `hotel-lobby-duo`。

## 4. 展示与视觉设计

继承 EzPic 的工作室风格：深紫外壳、安静的操作区、鲜明的真实成片。源站橙色仅作为视频内容中的颜色，不迁移整套橙白营销皮肤、点阵背景或点击特效。

| 设计项         | 建议                                                                                                                  |
| -------------- | --------------------------------------------------------------------------------------------------------------------- |
| 背景/卡片/主色 | 复用当前 `#19131f` / `#211a2a` / `#8065f5`；正文 `#f6f2fb`，次级文字 `#b8adbf`，焦点 `#b79cff`                        |
| 字体           | 沿用 Plus Jakarta Sans 与系统中日韩 fallback；不引入源站 Barlow/IBM Plex 的额外下载                                   |
| 字级           | 目录标题 32–40px，模板名称 16–18px，说明 14px，辅助信息 12px；按现有 tokens 校准                                      |
| 卡片           | 圆角 16–20px、轻边框；信息在封面下方，避免大量文字覆盖视频                                                            |
| 网格           | 常规 3–4 列，平板 2 列，手机 2 列；极窄屏或大字体退为 1 列；不做高低混排的瀑布流                                      |
| 封面           | 目录统一 4:5 展示框，优先单独制作并检查的裁切封面；缺少合适裁切时 contain。视频播放必须保持真实比例，不拉伸或裁掉主体 |
| 交互           | 选中与焦点共用紫色；160–200ms 轻微状态变化；不做弹跳、翻转和无意义轮播                                                |
| 特色           | 样片中的“人物 A/B/C”与上传槽位一致，突出“把谁放进哪个位置”；不要展示虚假的音频波形                                    |

桌面模板页布局：

```text
视频模板 / Spin Me Round                 [返回目录]
Spin Me Round         选择人物，制作同款旋转舞蹈
┌────────────────────────┬────────────────────────────────┐
│ 样片/新生成结果         │ [单人] [双人] [三人]           │
│ 保持原始比例            │ 上传人物 A / B / C             │
│ 播放、静音、放大        │ 场景：Empty room / Retro neon  │
│ 输入与输出简短说明      │ 时长 / 画质（只显示合法选项）  │
│ [示例] [我的结果]       │ 报价与积分 → 生成视频          │
└────────────────────────┴────────────────────────────────┘
当前任务 → 本模板历史 → 使用建议 / FAQ / 相关模板
```

高于 1100px：预览约 52%，表单约 48%，有效内容宽 1120–1280px。中等宽度等分。移动端顺序：标题 → 可折叠静态样片（不超过约 30vh）→ 人物/参数表单 → 主按钮 → 结果/历史。预览的“展开”进入播放器，不能让用户先滚两屏视频才找到上传。

手机底部可使用原主按钮的粘性容器；不得另造第二个提交实例。键盘打开时退出粘性，保留安全区和尾部空白，320/390px 与大字体均不能遮挡表单。

## 5. 从发现到完成的交互

1. 浏览封面，无需登录；“播放样片”与“使用模板”是两个明确动作。
2. 打开模板，先展示“需要几张照片、生成什么、声音与格式”。固定模板隐藏无效的模型/歌词/时长设置。
3. 人物上传具有角色标签：主角、左侧、右侧、宠物等；可交换位置。本地文件检查之后仍由服务端执行不可变素材和审核检查。
4. 原创说唱才显示主题/歌词、场景和适配时长；Bulin 等固定模板不假装能任意换词。不能将单人/双人输入支持误称为逐字演唱、声音克隆或 Battle。
5. 使用账户素材或图片结果时只传 owner-bound asset ID；服务端重新检查所有权、格式、配额、期限和引用资格。图片输出审核不能自动代替视频输入审核。
6. 展示当前合法组合的最终积分报价；点击“生成视频 · N 积分”。资格不足解释具体原因，充值完成后恢复当前模板和草稿。
7. 提交后出现真实阶段：准备素材、审核、生成、保存、完成。无真实进度时不造百分比或秒级承诺；用可观测 P50/P90 后再展示预计范围。
8. 完成后同一预览区切到“我的结果”，提供下载、再次创作、换模板；示例和个人结果的标签始终清楚。

状态约束：

- 切换模板不默认清空草稿；模板、账号、版本分别存草稿。可兼容的图片仅在显式“沿用照片”时转入角色槽；双人变单人不静默丢弃另一张。
- 未提交的报价随参数变化失效；已提交或未知结果的确认回执独立保留，继续恢复原任务，不能生成新幂等键重试付费请求。
- 登录交接保留可安全转交的模板与非敏感设置；File 跨登录不能保证恢复，重选照片时明确说明。歌词不放在 URL、分析事件或共享缓存。
- 目录/播放故障不清空创作；模板不可用时仍能读自己的历史。生成准入与结果读取是不同开关。
- 页面隐藏暂停媒体和不必要轮询；恢复可见后立即授权读取。后台 Workflow 继续执行。
- 账户历史统一提供“图片 / 视频”切换，视频内可选“全部 / 自由生成 / 模板”；模板详情仍显示本模板历史。第一阶段可在 `/history` 聚合标签中嵌入已有 `/video/history` 能力，避免一次重写所有查询。
- 键盘可完成菜单、上传、选择、播放与返回；44px 触控区域、可见焦点、Esc 关闭和焦点归还；减少动画与 Save-Data 默认静态。声音必须由用户主动打开。

## 6. 性能：预算先行，媒体与业务分离

以下数字是**设计预算，尚未测得**。实施先记录当前页面基线，并保留现有性能测试门槛。

| 层次     | 设计与验收目标                                                                                                    |
| -------- | ----------------------------------------------------------------------------------------------------------------- |
| 图片首页 | 浏览模板前新增 MP4 请求为 0；不加载模板执行表单/完整翻译/各供应商依赖；模板导航与推荐区新增 JS gzip 目标 ≤10 KiB  |
| 模板目录 | SSR 首批 12 项以内；核心文本与卡片不等登录请求。首屏加载 4–6 张适配尺寸的封面，合计目标 ≤300 KiB                  |
| 播放     | 初始只放 poster；选择/hover 意图持续约 200ms 后才挂预览源；全页单一活跃播放器，切页/离屏/切后台暂停并释放远处资源 |
| 预览素材 | 单独 360–540p、3–5 秒、无音轨短预览，目标约 0.3–0.8 MiB；实际声音播放使用完整样片。预览失败保留封面               |
| 创作交互 | 仅打开当前模板时加载其表单与 namespace；目录增量 JS gzip 目标 ≤35 KiB（不含已有框架）                             |
| 静态缓存 | 封面/短预览用内容哈希+长缓存；公共目录可缓存，个性化资格/报价/草稿/历史绝不进入共享缓存                           |
| 数据请求 | 目录无每卡一次 readiness 请求；批量公共投影，加一次当前模板的账户资格/报价读取；限制显式 prefetch 数量            |
| 用户体验 | 移动端 p75 目标 LCP ≤2.5s、INP ≤200ms、CLS ≤0.1；真实用户数据与本地 Lighthouse 分开报告                           |

不要直接复制源站“视口附近 240px 即挂载多个视频”的行为。它有按视口加载机制，但大目录会有多路解码和流量成本；在 EzPic 增加播放器协调，不把“进入视口”直接等同于“下载并播放”。

生成时延单独分段记录：上传、审核、入队、供应商、转存、可播放。不能用首页速度证明生成速度，也不能承诺供应商若干秒完成。多角色上传可以有界并行（建议最多 2 个），仍受既有字节/会话/存储配额约束。

服务端沿用 VIDEO_WORKFLOW 和现有 PostgreSQL 业务状态；视频流式读写，避免将整段音频/视频 base64 带入 Worker。公开展示不产生供应商调用。平台容量和模板数量解耦，不新增全局生成排队上限来掩盖页面性能问题。

## 7. 工程融合：统一体验、分型合同

原站使用 TanStack Start / Paraglide，当前项目是 Next.js / next-intl / oRPC。直接复用其提示词、纯函数、schema、请求构造和测试；展示组件能复用的布局/逻辑继续复用，只改路由、翻译、主题和 API 接口。无需为了迁移重写模板核心，也不需要嵌 iframe。

### 直接复用清单

优先将小范围纯逻辑复制并保留来源记录到目标站的 server-only 模块；不建立运行时跨仓库相对路径依赖，也不为本次迁移先建设公共 npm 包。稳定后如两站确需同步，再提取共享包。

源 JSON 默认值与源站管理员当前生效配置必须区分。实施时导入实际需要的有效模板版本与覆盖项，记录差异；不能仅复制示例 JSON 就宣布完整复现，也不把含敏感配置的整张 config 表复制过来。复用已有有效授权记录；只有缺失的素材权利或目标站使用范围再补证据，无需重复询问已经给出的代码/提示词复用许可。

验证重点由“重写后效果类似”改为“同一模板/参数的 prompt 与请求语义保持一致”：使用来源测试向量核对模板文本、角色顺序、音频、分镜和参数；仅允许预期的素材授权 URL、callback、应用 ID 等边界差异。与旧账本/存储绑定的服务不整体搬入。

在现有模块中分清三个职责，不新建一套平行平台：

1. **公共模板目录**：`templateKey`、名称、分类/标签、输入角色、允许输出选项、样片来源、展示状态、canonicalPath。只投影浏览器真正需要的信息。
2. **私有执行合同**：模板版本、provider/route、冻结 prompt、管理员素材与授权、音频策略、完整成本、输入/输出校验。客户端只提交稳定 key 和用户允许的选择。
3. **统一体验组件**：TemplateCard、TemplatePreview、TemplateWorkspaceShell、TemplateInputs、TemplateOptions、QuoteAction、JobStatus；按类型扩展少量专用字段，不堆一个无边界的万能表单。

执行类型至少区分：已有两阶段场景生成 → 视频、原创说唱、固定参考音频/图像模板、动作视频参考模板。公开 UI 用“说唱/舞蹈/宠物”等结果语言，provider 名、内部阶段和审核合同留在服务端。

### 接入差异不能靠改模型名称解决

- 源站主 Rap/Spin/Bulin 路径存在 SeeAPI 视频生成，58th/短效果走 Kie H3；当前 EzPic 的普通视频目录虽然有相关模型，不等于支持源站的 reference 模式。
- 已有 Kie Seedance reference adapter 是受限的 5 秒/720p/9:16/静音+图像/视频参考合同，不能直接接收 Bulin 的 15 秒参考音频或 Spin 的多角色参数。
- 复用源请求代码并在 EzPic 的 provider adapter 边界补齐源合同；不因目标站已有某个同名模型就替换源执行路径。原合同缺失或不可用时标明缺项，不能自行选“等效模型”、降低画质、改变时长或去掉声音。
- 所有新任务继续在一个事务内保存输入绑定、版本快照、积分预留和执行意图；不复制源站另一套可变余额和公开成片机制。
- 模板采用有类型的角色数组，而不是永远绑定 left/right。旧请求由兼容转换读取，不能重写旧回执。
- 新模板默认关闭生成；每个模板有独立展示/准入状态和适用人群，不放大 Hotel Lobby/Raindance 的既有开放范围。

### 定价与素材

源站的 10 credits 与 EzPic 的 10 credits 不能直接比较。目标站单独算：视频生成、可能的场景图、审核、转存/带宽与失败成本，再确定版本化零售价。使用目标站现有有效共享积分，不复制源站兑换比例，不让图片 3 张通行证覆盖视频。

源模板包至少记录：稳定身份/版本、来源及权利依据、样片类型（外部参考/目标站实际生成/概念）、不可变素材 ID/hash、输出规格、来源合同、迁移状态、质量验证记录。字段为“未验证”时保持空值，不生成虚构 verifiedAt。样片可以展示源站结果并注明来源，但不能冒充 EzPic 验收结果。

发布前核对公开样片及声音能否用于目标站的展示和生成引用。用户照片、生成结果和私有参考素材保持受控；公共封面与私有生成参考不能共用公开地址。已有动作或声轨不会自动赋予声音克隆、名人代言或音乐再授权能力。

## 8. 内容、SEO 与运营

- 保留首页 `ai image editor` 定位。模板目录承担视频发现，独立工具页承担真实具体任务；不复制源站全部文案再期待两个站自动得到独立排名。
- 新公开路由加入 proxy matcher，按现有英语裸 URL 与真实 de/es/fr 翻译策略处理；英语 fallback 维持现有 noindex/canonical 规则。zh 源文案不能直接当作目标站现有语言体系。
- 筛选、私人任务、草稿/支付恢复参数不作为可索引内容。只在页面、样片和工具可用且经过内容复核后进入 sitemap。
- 不创建新的图片 Effects 目录；Photo Ideas 的 Blog canonical 不变。Raindance 的文章和嵌入模板仍是一套内容身份。
- 原 ezrapvideo 域名默认继续运行，不添加全站 301/cross-domain canonical，也不迁移商家订单。若未来关站或整站迁移，另做 URL/权益/支持方案。
- 管理端第一版提供轻量导入清单、预览、样片/合同状态、展示排序、单模板启停和版本回退；不建设拖拽式模板设计器。
- 发布流程：草稿 → 合同与素材检查 → 有授权的效果验证 → 就绪 → 公开展示/开放生成。公开展示与生成开放可以不同，但 UI 必须明确可用性。

## 10. 验收与观测

设计验收：目录能看出模板做什么、需要什么、是否有声音；模板页从首屏能找到输入；图片与视频风格一致；手机不依赖 hover；不可用、待验证与可用状态明确。

实现时重点回归：

- 320/390/768/1440px、键盘/屏幕阅读器、减少动画、慢网/播放失败、左右角色交换和三人模式。
- 模式切换、登录返回、换账号、刷新未知提交、价格变化、报价过期、充值返回；断网不能重复预留/扣款。
- 私有素材隔离、owner 校验、引用期限、音频/动作参考、回调鉴权、结果访问、模板下架后历史读取。
- 图片首页未访问模板时不请求 MP4、不加载完整模板引擎；目录一次最多一路播放；隐藏页暂停；旧页面性能门槛保持。
- 使用受影响的现有测试：`VideoWorkspace.test.tsx`、video-effects 的 model/history 测试、API/数据库积分与幂等测试、provider 合同测试、公共索引与性能 E2E。财务与新 provider 合同变动必须扩展跨层验证。

新增事件复用现有分析和同意机制：曝光（可见后一次）、模板详情、播放、开始输入、报价、提交、成功、下载、图片→视频。字段只用模板/版本/来源入口/状态等非敏感维度；不记录照片 URL、歌词或 prompt。关注详情到提交率、成功并下载率、图片到视频转化、每成功任务的实际成本及退款率；没有数据前不显示“热门/最快/最受欢迎”。
