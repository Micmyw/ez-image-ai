# Hotel Lobby duo PRD T01–T26 test and recovery map

This is a source-level evidence map for section 14 of `ezimage-hotel-lobby-video-codex-prd.md`, not a real-service acceptance certificate. Exact execution commands, final counts, build results and authorization boundaries belong to [the verification receipt](../operations/hotel-lobby-verification.md). Test names below are literal names or the literal parameterized name (`%s`, `%j`).

After the T03/T14/T16/T18 and late-callback recovery additions, the final concentrated run includes **23/23 template PostgreSQL cases** and **280 total database/jobs cases passed, 3 optional performance cases skipped**. Its wall-clock duration was 87.069 seconds. This is isolated local PostgreSQL evidence. No real provider, paid moderation, R2 delivery or production acceptance follows from it. Other entries identify the relevant test source; consult the receipt for their latest run result rather than treating file existence as a pass.

## Evidence boundaries

- **PG**: actual PostgreSQL transactions, constraints, locks, triggers, ledger and accounting using disposable fixtures. Provider and storage content in these tests are fixtures.
- **SQL + HTTP fixtures**: real database and production domain functions/orchestrator, with provider, moderation and transfer boundaries substituted. Synthetic MP4/image identities are not generated product examples.
- **Unit/Mock**: deterministic local mocks, public schema/parser checks, component rendering or synthetic media decoding.
- **Browser Mock**: the real local page with auth, RPC and upload routes intercepted. These tests do not prove authenticated production uploads, real billing or real generation.
- **Local workerd**: the actual local native Workflow runtime with mocked stage bodies; this proves durable step behavior, not cloud deployment or provider acceptance.
- **Isolated MinIO**: actual local S3-compatible I/O and real decoder behavior. It is not R2 or a provider-owned object.

All live paid generation, actual SeeAPI/Waffo acceptance, real R2 playback, production migrations/deployment, real payment completion and candidate visual-quality results remain **NOT_RUN** or **BLOCKED**, as specified in the verification receipt.

## Recovery interpretations that must remain explicit

1. A scene or final-video paid may-have-sent fence is not a retry permission. Unknown acceptance preserves the same reservation and requires recovery of that original request.
2. The scene task ID and authenticated callback may become known while the parent remains NEEDS_REVIEW. A callback is not authorization to restart a finished Workflow, resubmit either provider or refund an uncertain order. Operator recovery must preserve the same frozen job and identities.
3. The SQL tests deliberately simulate failed storage and then call the cleanup-completed function. Only the production cleanup caller's successful deletion permits that call; SQL alone cannot prove a remote object was physically removed.
4. Scene content REVIEW/ERROR and final SeeAPI uncertainty stay held. Known input/scene/video REJECT can fail the single order exactly once. Known successful scene work does not prevent release after a definite pre-video failure, while its physical bytes remain counted until deletion.
5. Template image metadata/status recovery can return no preview URL before checksum-bound input approval. Reissued previews do not bypass owner, identity, policy or expiry checks.
6. No tests in this map establish dual-person likeness, alternating motion quality, merchant account permissions, real costs, twelve-group quality acceptance or sample rights. Those gates remain in the verification receipt.
