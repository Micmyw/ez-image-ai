# EzPic Cloudflare runtime constraints

Read for job/runtime/database packaging or deployment changes. Operational cutover, drain, rollback, bindings, and live checks remain in `docs/operations/cloudflare-workers-profiles.md` (repository-root path).

## Jobs

- Video runs directly through the native `VIDEO_WORKFLOW` binding and the versioned `VideoGenerationWorkflowV1` in both profiles. Its PostgreSQL `VideoExecution` start intent is committed with the job and reservation; normal progress does not dispatch WorkerJobs or scan global Outbox. Keep legacy engine guards in callback, recovery, moderation, administration and settlement paths. New requests freeze Waffo prompt review, SeeAPI visual review and `audioSafetyPolicy={schemaVersion:1,mode:'not_requested'}`; native sound remains supported without transcription or audio-review calls. Sightengine is retired, including old-job draining; unfinished work requiring retired checks is held, while historical READY access remains bounded by its existing evidence and authorization. Technical moderation failures never authorize bypass. Uncertain paid submissions are never automatically repeated. See [video drain/rollback](../operations/video-v1-rollout.md).

- API work uses `dispatchJob` from `@repo/jobs/orchestration/client`. `WORKFLOWS_DISPATCH_URL` includes `/internal/dispatch` and requires HTTPS in production. SaaS and Worker share a random `WORKFLOWS_DISPATCH_SECRET` of at least 32 characters.
- `apps/workflows` owns durable dispatch/retry/sleep and scheduled maintenance. Both profiles use signed, request-owned `ControlExecutor` and `TransferExecutor` service entrypoints with Hyperdrive/Prisma and Cloudflare Images. Bind `JOBS_CONTROL` and `JOBS_TRANSFER` to the selected jobs script and corresponding entrypoints. Default `workers` retains private `WorkerJobs` for legacy buffered work and maintenance; `hybrid` retains `apps/jobs-runtime` with Sharp for those paths.
- Normal lightweight requests and eligible ordinary URL-image transfers have no application-wide count-based queue. Before streaming, project only bounded remote URLs from the authoritative envelope, reject incompatible state, and check actual MIME/length; use backpressure up to the existing 25 MiB image limit. Legacy `jobs-primary` (1), `jobs-control` (4) and `jobs-maintenance` (1) remain for compatible draining and work requiring the old resource guard. Routing and inline-child boundaries live in `packages/jobs/src/orchestration/worker-executors.ts`. A typed pre-transfer exclusion may reroute the identical receipt/context to heavy execution; an unknown transport outcome never may. Object names do not provide independent 128 MB memory allocations.
- Normal first-image stages return a bounded continuation containing actual committed event IDs, or the original accepted attempt ID for polling in the same Workflow. `media-deliver-events` claims these events on control through the existing lease/receipt protocol; capacity limits and asset query due times still apply. An explicit empty continuation never triggers a global scan. `media-deliver-output-review` and absent-continuation responses remain compatible for old Workflows. Scheduled scanning remains the crash, lease-expiry and receipt-recovery path. Normal PENDING never spends finalization failure retries. See `docs/operations/first-image-scanless-batch-2026-09-30.md` before claiming cloud latency gains.
- Workers use separate credential bindings and injected contexts. Non-secret video policy is packed into the private `VIDEO_RUNTIME_CONFIG` JSON binding by `packages/config/video-runtime-environment.ts`; its fixed key allowlist excludes credentials, resource bindings, public variables and the independent `VIDEO_V1_ENABLED` / `HOTEL_LOBBY_DUO_ENABLED` admission switches. Values remain strings and the encoded payload is limited to 5,000 UTF-8 bytes. Flat configuration stays compatible, but conflicting flat/packed values stop preparation. Website fetch, native video services/steps/recovery and legacy WorkerJobs entrypoints hydrate an effective snapshot before business code reads `process.env`; the website passes that same snapshot into OpenNext. Invalid runtime policy clears policy fields and closes both video admission switches without disabling image work. Both switches default closed and are mirrored to website/background Workers; never infer them from a valid policy pack. Origin credentials stay in Hyperdrive with verified TLS and query caching disabled. Hybrid containers receive the already expanded `JOBS_RUNTIME_ENV` JSON secrets at startup; never embed credentials or allowlists in public variables.
- Kie image submissions use an attempt-bound HMAC completion URL, derived with a separate purpose string from the existing `WORKFLOWS_DISPATCH_SECRET`. Website and jobs must share that secret and `NEXT_PUBLIC_SAAS_URL`. A callback can only make a matching, active attempt due for leased provider retrieval; callback status and output URLs never become business evidence. Polling and scheduled recovery remain active after missed callbacks or secret rotation.
- The signed execution envelope opts in to `supportsImmediatePolling`. Only opted-in callers receive pending zero-wait retries after a successful query releases its lease and an authenticated callback has left it immediately due. Moderation retries are bound-task `queryOnly` operations. Failed reads, active leases, future backoff and uncertain acceptance retain their existing protections. Keep the old response floors for old Workflows during receiver-first rollout and draining.

- Image verification commits READY/evidence/continuations/notification intent before starting its notification fast path. ControlExecutor, TransferExecutor and Workers WorkerJobs register a request-owned lifetime with `waitUntil` before business execution; deferred notification delivery, its database ACK and registered descendants finish before that request's database client disconnects. Without a platform lifetime, drain before returning. Keep the durable Outbox recovery, per-request client isolation and notification feature gate; a bare discarded Promise or a shared active PrismaClient is not equivalent. This does not change phase event names or introduce an admission cap. See [the live-result follow-up](../operations/generation-live-followup-2026-10-23.md).
- The signed `supportsDatabaseConflictRetry` capability accepts only two receipt-bound 503 combinations: finalization's nominal `OutputTransferClaimConflictError` / `OUTPUT_TRANSFER_CLAIM_CONFLICT` / `BEFORE_TRANSFER_LEASE`, and settlement's nominal `SettlementTransactionConflictError` / `SETTLEMENT_TRANSACTION_CONFLICT` / `TRANSACTION_ROLLED_BACK`. The former proves a rolled-back candidate claim (earlier persisted candidates are reused); the latter is constructed only at the settlement transaction's confirmed-rollback boundary. Generic codes, unknown commits, transport failures and other financial/Stripe tasks never authorize retry. Direct wakes hand the same receipt to durable execution; Workflows use their existing finite attempt budget without a retry sleep. Begin atomically writes `EXECUTION_IN_PROGRESS:<UUID>` with lease renewal; late failure, safe-clear and targeted ACK writes also match that execution UUID. Unknown failures retain that guard even if writing `RECOVERY_REQUIRED` fails. Query-only review can cross only `RECOVERY_REQUIRED`, becoming `RECOVERY_QUERY_IN_PROGRESS:<UUID>`; safe PENDING restores the prior unknown hold. Neither query nor ordinary execution crosses an in-progress guard. Successful ACK clears the guard in its existing write, while a new lease/token claim clears old execution markers only through normal due/expiry recovery. Failed prepare handoffs retain foreign-lease waits. Deploy Workers/control/transfer and hybrid receivers before new adapters; old callers retain generic failure responses and the same guard. Logs project whitelisted codes and phases only, never raw errors, payloads or private URLs. See [receipt recovery](../operations/image-workflow-continuation-2026-10-22.md).
- New immediate Outbox intents use the database-generated `availableAt` default from `20261021210715_outbox_database_clock`; Prisma `@default(now())` materializes the application clock and is not an equivalent client contract. Targeted prepare and receipt claim/begin/complete use PostgreSQL time by default. Unavailable live events return a remaining duration, which the invoking Workflow converts to its own persisted deadline before waiting for the same event. Direct callback wakes hand off the event ID to durable execution. Preserve future due times, active leases, completion receipts and explicit test clocks; never compare a database timestamp with an application timestamp as a certified scheduling delay.
- Runtime immediate enqueue collectors and pending-image poll intents also omit an application-side `availableAt`; existing future events retain their due time on deduplication, and explicit non-pending retry backoff remains unchanged. Workflow waits skip an elapsed local deadline and recheck the same event. Future waits retain their original `sleepUntil` name and absolute value; if that sleep call fails after the local deadline elapsed, the wrapper may continue, but an error before the deadline still propagates. The catch does not cover event preparation, executor invocation or paid handlers. Keep receipt recovery and finite preparation budgets; a failed or unknown execution is never permission to replay it.
- Explicit `eventIds` claim through the existing single atomic `FOR UPDATE SKIP LOCKED` / `UPDATE RETURNING` statement without an extra Serializable wrapper. Caller-owned transactions are reused; global scans and legacy `outputReviewEventId` claims retain their prior isolation. All paths share row locks, due/lease rules and execution guards. An unknown query response never authorizes a fresh paid execution or automatic replay. This changes neither the persisted receipt format nor durable Outbox recovery.
- Review PENDING handoffs retain the receiver's remaining wait through `notBefore`, while the review Workflow identity excludes the locally calculated deadline so duplicate wakes do not create extra pollers. Submission/binding condition updates run after the advisory-lock statement with a fresh snapshot. Expired binding leases may record the accepted provider identity for query-only recovery, never resubmit it. Local Miniflare uses direct database connections unless the test harness explicitly selects its local transaction pool; socket lifetime in that fixture is not evidence of production Hyperdrive backend occupancy. See the [v7 local comparison](../operations/generation-one-second-budget-2026-10-22.md#v7-最终本地对照并发通过一秒仍未认证) before interpreting local connection-limit errors or latency.

- New image Workflow adapters use `media-prepare-event` and strict Outbox receipts to continue in the original Workflow. Prepare releases its control slot before the child enters its classified lane; independent events have bounded concurrency without raising heavy capacity. Renew the exact receipt before execution, never ACK PENDING moderation, and recover a processed lost response without replaying the paid handler. Retain old receivers/protocols during drain and deploy compatible receivers first; see [same-Workflow continuation](../operations/image-workflow-continuation-2026-10-22.md).
- Persisted image Workflow parameters with `executionVersion: 2` use `media-execute-event`: control preparation, receipt-bound execution and ACK share one request scope. Transfers and buffered work return the classified child receipt instead of running inside control. A lost wrapper response permits only `recoverOnly` observation; completion recovers committed continuations, while an uncertain execution stays held. PENDING never ACKs, and an expired continuation receipt must return to event preparation. Parameters without the version retain the original prepare/child step names during drain. Inline business-stage diagnostics do not represent additional executor requests.
- V2 image moderation and provider polling use `media_workflow_phase_owner`, keyed by asset plus review generation or provider attempt. Apply `20261022022231_image_workflow_phase_owner` before readers/writers. The private owner includes a Workflow ID, opaque phase key and epoch; business leases, uncertain acceptance and immutable evidence remain authoritative. Signed `/internal/phase-wake` sends a phase-specific Workflow event only after callback persistence. Missing/failed signal delivery never starts a competing direct execution; durable timeout and recovery remain. Do not derive ownership from a job that happens to reference a shared asset, infer a Workflow ID from a generic run ID, or treat an accepted signal as a reviewed result. Deploy compatible Workers and hybrid Node receivers before V2 producers and retain ownership fences while accepted V2 work drains.
- Generic provider webhook recovery blocked by a live phase owner or processing lease retains and defers the original Outbox event using the remaining lease duration. It neither ACKs nor spends the failure retry budget. Successful inline recovery transports its bounded committed `continuations[]` after ACK; the parent follows every item after maintenance resources are released, including the last scan. Keep each item's due time, attempt and phase identity. Deploy compatible Node/Workers response transports and Workflow consumers before inline producers and retain legacy singular response handling during drain.
- Fresh asynchronous SeeAPI image submissions skip the immediate GET only when the authenticated raw POST reports queued/processing with no result, the runtime has a valid signed callback URL, and provider task binding succeeds with an active lease and current owner. A completed decision has priority; unified RUNNING alone is insufficient. Old adapters, missing callbacks and ambiguous responses retain the GET. The existing locked PENDING write preserves early callback evidence, releases the business lease and retains durable query-only polling; lost callbacks and unknown acceptance keep their recovery rules. The advisory lock remains a separate statement before submission/binding writes. Owner validation is fused into submission's guarded UPDATE and accepted binding's RETURNING; late accepted provider identity must not be discarded by an owner predicate in binding's WHERE.
- SeeAPI image callbacks require purpose-separated asset/generation/submission proofs plus raw-body verification using existing `SEEAPI_WEBHOOK_SIGNING_KEYS`. Persist the first valid notification in the current generation's `verificationCallbackReceivedAt`; early or active-lease callbacks return 202 without stealing ownership. PENDING commits preserve immediate retry when a newer callback arrived during the query. Missing callback configuration preserves polling. An authenticated synchronous submission verdict is usable only after binding the task with a live lease. New output transfers reuse the policy-checked media detection stream through direct or staging writes and always close it; recovered immutable output objects remain independent of expired provider URLs.
- New adapters commit the first output-review event atomically with the private output and release the heavy executor before starting review. Legacy callers retain inline behavior while draining. Callback fast wakes use signed `/internal/wake`, the same database leases and receipt completion; every asynchronous continuation must retain durable polling recovery. Capacity release wakes bounded waiters without a fixed five-second sleep, while legacy zero-wait receivers remain compatible. Never ACK an accepted or PENDING operation as completed.
- Owner-scoped result notifications use `MediaJobEvents` and `MEDIA_JOB_UPDATED` durable Outbox intents, with bounded best-effort publication after commit. `MEDIA_JOB_EVENTS_ENABLED` defaults off; deploy consumers first and drain incompatible old consumers before enabling producers. Both profiles require the `media-job-events-v1` SQLite DO migration; the website binds `MEDIA_JOB_EVENTS` and `JOBS_DISPATCH` to its selected jobs script. Preserve the DO, signed ingress and consumers when disabling producers. Same-origin WebSocket upgrades bypass OpenNext's HTTP bridge inside the normal request scope; messages contain only job/event/version and trigger a fresh authorized status read. Reconnect refresh and polling remain recovery paths. Apply the nullable callback-wake migration before the new database consumers. See [one-second budget and rollout](../operations/generation-one-second-budget-2026-10-22.md).
- Native video stores a lease-committed complete-stream inspection receipt bound to its frozen specification and immutable object identity. Matching receipts allow conditional one-byte availability checks before review/delivery; missing or historical receipts retain full inspection. READY state can include an owner-bound short-lived playback grant from the same authorization projection. Playback GET/Range uses one conditional read, preserving private authorization and identity validation. See [generation critical path](../operations/generation-critical-path-2026-10-22.md).

- `VIDEO_V1_BUILD_ENABLED` is a dedicated build-only override, never a packed policy or runtime binding. Exact `true` requires a valid `VIDEO_RUNTIME_CONFIG` override in the same build with a nonempty model allowlist accepted by the current contract; exact `false` can independently close admission. The builder appends only the authoritative `VIDEO_V1_ENABLED` dotenv value and verifies that unrelated fields remain unchanged. Ambient `VIDEO_V1_ENABLED` is always ignored by build overlays. Runtime readiness and user/model/funding gates remain mandatory after this explicit build control.
- `HOTEL_LOBBY_DUO_BUILD_ENABLED` follows the same separate build-only transport for the template. Exact `true` additionally requires ordinary video enabled and the complete template version, fixed model option, confirmed costs and unexpired price evidence. Exact `false` closes only new template admission. Ambient `HOTEL_LOBBY_DUO_ENABLED` cannot override the authoritative dotenv bundle. Template policy/funding is private in the existing packed binding; ordinary `VIDEO_INTERNAL_FUNDING` is not inherited as template test authorization. Disabling new admission must retain receiver, frozen execution and private assets for accepted orders.

- `HOTEL_LOBBY_DUO_RUNTIME_CONFIG` is a private build-only patch over the build runner's existing `VIDEO_RUNTIME_CONFIG`, never a replacement from a stale local snapshot or a second runtime policy. Its fixed allowlist permits template access/price/version fields, excludes funding and admission switches, and can append only the fixed Seedance 1.5 Pro I2V/5s/720p/silent option without widening existing groups. `HOTEL_LOBBY_DUO_ACCESS` defaults to internal and supports authenticated template accounts independently of ordinary `VIDEO_V1_ACCESS=internal`. Both workers receive the same merged private policy, with a 5,000-byte bound. See [template overlay preparation and rollback](../operations/hotel-lobby-build-overlay.md).
- Ordinary untransformed JPEG/PNG/WebP URL outputs of known length up to the existing 25 MiB image limit use one streaming private `If-None-Match: *` PUT after quota reservation. SHA256 and actual byte count are computed during transfer and committed in the database only after complete validation; the last byte is withheld until source EOF so truncated or overlong sources cannot leave an adoptable prefix. Recovery fully reads and validates the immutable winner and rechecks the transfer fence before DB completion. Guest watermarking, inline payloads, video, unknown lengths and persisted multipart transfers retain their prior guarded paths. Direct transfers retain old staging metadata for rollback but never write that staging key or delete the final key as staging.
- `pnpm workflows:type-check` checks orchestration/Node boundaries; `pnpm cloudflare:jobs:build` builds Workers artifacts; `pnpm workflows:build:ci` builds hybrid artifacts without Cloudflare credentials. Container build/execution needs Docker.

- The pinned Prisma 7.9.1 edge runtime patch reuses decoded parameterization-schema data through a weak cache. Changes to the encoded graph or string table invalidate the entry. Later independent clients retain the original eager lifecycle; this is not a guarantee of original-loader panic recovery. Keep the package patch, installed CJS/ESM, real WASM/GC, PostgreSQL isolation/default/error and workerd regressions together when upgrading Prisma. Validate known-facade provenance before choosing a private hit; for a tracked shared template, recheck its compiler epoch after execution arguments are evaluated. Keep regression coverage for owner/parameter/transaction isolation, warmed private hits after soft/hard failure and synchronous reentry when updating the patch.
